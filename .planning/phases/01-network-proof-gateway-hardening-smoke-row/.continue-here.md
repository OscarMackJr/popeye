# BLOCKING CONSTRAINTS — Read Before Anything Else

> Each constraint below was discovered through failure. Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: Empty reads are not clean results. A check that read nothing (stderr discarded, data-plane call blocked by the proxy, wrong filter, or a log level that hides the line) is NOT a PASS. Structural mitigation: every log or query check must first show that it read data (row count > 0 or a known-present line) before it asserts the absence of errors.

**Do not proceed until the box is checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Vacuous pass on empty log read | 01-04 Health ran `az containerapp logs show ... 2>$null`. Behind the operator's TLS-intercepting proxy it returned nothing, so "no ConnectionError/MOVED/CROSSSLOT" passed without reading anything. A later portal query that counted 0 errors only meant something after a per-revision row count showed 22,826 rows. | blocking | The cutover script now throws on an empty or failed read. For any absence check, run a row-count or presence query first and record the count in the evidence. |
| Worktree executor on a stale base | The 01-06 executor's worktree started at origin/main (e1e8850), not local HEAD, so `git merge --ff-only` failed. | advisory | Before the ff-merge, run `git merge-base main <branch>`. If it differs, `git rebase --autostash main <branch>`, re-run fmt/validate, then fast-forward. |
| `git pull --rebase` over unpushed merge history | It flattened 4 merge commits and rewrote 35 hashes, so SUMMARY commit references went stale. | advisory | `git fetch` and inspect `main..origin/main` first. Fix SUMMARY hashes after any history rewrite. |
| Windows az.cmd quoting | `--query` strings with `(`, `,`, `'`, `?` or `==` get mangled in PowerShell. | advisory | Use plain JMESPath (`[].name`, `[0].image`) and filter with `Where-Object`/`ConvertFrom-Json`. |
| Data-plane az blocked by the proxy | `containerapp logs show` and `monitor log-analytics query` fail CERTIFICATE_VERIFY_FAILED on the workstation. Management plane and `containerapp exec` work. | advisory | Read logs in the portal: Log Analytics `popeye-stage1-stage2-eastus2-law` → Logs → KQL mode, table `ContainerAppConsoleLogs_CL` (columns `RevisionName_s`, `Log_s`). |
| KQL gotchas | `last` is reserved, and `union withsource=X *` collides with existing columns. Operators also paste the `kusto` fence label. | advisory | Use `newest`/`latest` as names, use `Usage` for per-table ingestion, and give queries in unlabeled code blocks. |
| Executor sandbox has no network | GHSA, release and GHCR digest checks cannot run in the subagent. | advisory | Do pin-day network checks in the main session (`gh api`, anonymous GHCR token + manifest HEAD). |
| `LITELLM_LOG=ERROR` hides INFO evidence | The new revision prints only the banner and the Prisma line, so the `coordination_redis` boot line is not observable. | advisory | Prove GW-06 behaviorally (01-08 cross-replica counter). Do not expect INFO log lines as evidence. |
